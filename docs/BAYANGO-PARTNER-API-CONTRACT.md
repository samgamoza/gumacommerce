## 1. Basics

| Item | Value |
|---|---|
| Base URL | `BAYANGO_API_BASE_URL`, e.g. `https://api.bayango.guma.one/partner/v1` (no trailing slash) |
| Auth | `Authorization: Bearer <BAYANGO_API_KEY>`. One key per partner (Guma Kart). Keys are stored hashed on the BayanGo side, can be rotated, and can be revoked. |
| Content type | `application/json; charset=utf-8` |
| Money | **Integer centavos** (`…Cents`). Currency is always `"PHP"`. |
| Coordinates | Decimal degrees as **numbers** (`{ "lat": 14.5547, "lng": 121.0244 }`) |
| Time | ISO-8601 UTC strings (`2026-10-02T08:15:00Z`) |
| Idempotency | Every `POST` accepts an `Idempotency-Key` header. A repeat with the same key and body returns the **original** response. `POST /deliveries` is also unique on `externalRef`. |
| Timeouts | Guma waits **10 s** per call, then treats the call as failed and fails over to another courier |
| Errors | `{ "error": { "code": "string", "message": "string" } }` with HTTP 400 validation, 401 bad key, 404 not found, 409 conflict / not cancellable, 422 `not_serviceable` or `quote_expired`, 429 rate-limited (honour `Retry-After`), 5xx |

The partner principal must **never** be treated as a customer, rider or admin, and must only see deliveries it created.

## 2. Endpoints

### 2.1 `POST /serviceability`

Cheap pre-check, called before quoting. It must not reserve anything.

```json
// request
{
  "pickup":  { "lat": 9.7392, "lng": 118.7353, "psgcCityCode": "175316000" },
  "dropoff": { "lat": 9.7500, "lng": 118.7400, "psgcCityCode": "175316000" }
}
// 200
{ "serviceable": true }
// or
{ "serviceable": false, "reason": "outside_service_area" }
```

`psgcCityCode` is optional. BayanGo may decide serviceability from its service-area list, from online riders near the pickup, or both.

### 2.2 `POST /quotes`

Server-side pricing. **BayanGo must compute distance and fee from the coordinates itself**; it must never trust a distance or fee sent by the client.

```json
// request
{
  "pickup":  { "address": "Rizal Ave, Brgy. Maunlad, Puerto Princesa", "lat": 9.7392, "lng": 118.7353 },
  "dropoff": { "address": "Malvar St, Brgy. San Miguel, Puerto Princesa", "lat": 9.75, "lng": 118.74 },
  "vehicleType": "motorcycle",
  "codAmountCents": 125000
}
// 200
{
  "quoteId": "qt_01J…",
  "feeCents": 8900,
  "currency": "PHP",
  "etaMinutes": 35,
  "distanceKm": 2.4,
  "expiresAt": "2026-10-02T08:30:00Z"
}
```

Quotes are persisted and expire after ~15 minutes. Booking with an expired quote returns 422 `quote_expired`.

### 2.3 `POST /deliveries` (book)

```json
// headers: Idempotency-Key: <Guma order id>
// request
{
  "quoteId": "qt_01J…",
  "externalRef": "8f0c…-guma-order-uuid",
  "merchant": { "externalId": "guma-tenant-uuid", "name": "Tita Bea's Closet", "phone": "+639171234567" },
  "pickup": {
    "address": "…", "lat": 9.7392, "lng": 118.7353,
    "contactName": "Tita Bea's Closet", "contactPhone": "+639171234567", "notes": "Gate 2"
  },
  "dropoff": {
    "address": "…", "lat": 9.75, "lng": 118.74,
    "recipientName": "Marites Santos", "recipientPhone": "+639181112222", "notes": "Green gate"
  },
  "payment": { "type": "prepaid" },            // or { "type": "cod", "codAmountCents": 125000 }
  "scheduledPickupAt": null,                    // optional ISO time; null = ASAP
  "remarks": "GK-0042"
}
// 201 (or 200 when replayed with the same Idempotency-Key / externalRef)
{
  "deliveryId": "dlv_01J…",
  "status": "pending",
  "feeCents": 8900,
  "trackingUrl": "https://track.bayango.guma.one/dlv_01J…"
}
```

**Rules on the BayanGo side**
- The fee comes from the stored quote; client money fields are ignored.
- `payment.type = "prepaid"` means **no** BayanGo payment record is created for the order value. Only COD creates a collection.
- The recipient **delivery PIN is generated by BayanGo and sent by SMS to `recipientPhone`**. It is never returned to the partner and never shown to riders.
- A duplicate `externalRef` returns the existing delivery and **never errors with a 500**.

### 2.4 `GET /deliveries/{deliveryId}`

Returns the same object as the webhook `delivery` payload in §3.2.

### 2.5 `POST /deliveries/{deliveryId}/cancel`

```json
// request
{ "reason": "merchant_cancelled" }
// 200
{ "deliveryId": "dlv_01J…", "status": "cancelled" }
// 409 when already picked up / terminal
```

## 3. Webhooks (BayanGo → Guma)

### 3.1 Transport and signing

- `POST https://kart.guma.one/api/webhooks/bayango`
- Headers:
  - `X-BayanGo-Event-Id: evt_…` (unique per event; Guma ignores repeats)
  - `X-BayanGo-Timestamp: 1790924065` (unix **seconds**)
  - `X-BayanGo-Signature: <hex>`, where `hex = HMAC_SHA256(BAYANGO_WEBHOOK_SECRET, "${timestamp}.${rawBody}")`
- Guma rejects requests with a bad signature or with a timestamp more than **5 minutes** from now (401).
- Any 2xx is an acknowledgement. On a non-2xx or a timeout, BayanGo retries with exponential backoff (1 m, 5 m, 30 m, 2 h, 6 h, 24 h), then marks the event dead.
- Events must be written to an **outbox in the same transaction as the status change** (in `DeliveriesService.transition()`), then delivered by a worker. Never send webhooks inline from the request.

### 3.2 Body

```json
{
  "eventId": "evt_01J…",
  "type": "delivery.status_changed",          // or "delivery.location"
  "occurredAt": "2026-10-02T08:20:00Z",
  "delivery": {
    "deliveryId": "dlv_01J…",
    "externalRef": "8f0c…-guma-order-uuid",
    "status": "picked_up",
    "trackingUrl": "https://track.bayango.guma.one/dlv_01J…",
    "rider": { "name": "Jun R.", "phone": "+639190000000", "plateNumber": "ABC 1234", "vehicleType": "motorcycle" },
    "location": { "lat": 9.741, "lng": 118.736, "at": "2026-10-02T08:19:55Z" },
    "failureReason": null,
    "proof": { "recipientName": "Marites", "photoUrl": "https://…" }
  }
}
```

`rider`, `location`, `failureReason` and `proof` are optional and appear when relevant. `delivery.location` events carry only `deliveryId`, `externalRef`, `status` and `location`; send at most one every 30 s per delivery.

### 3.3 Status vocabulary (partner-facing)

| Partner status | Meaning | BayanGo internal today | Guma order effect |
|---|---|---|---|
| `pending` | Booked, looking for a rider | `requested`, `finding_rider` | — |
| `assigned` | Rider accepted | `rider_assigned` | — (rider shown) |
| `pickup_scheduled` | Scheduled pickup confirmed | *new* | — |
| `picked_up` | Rider has the parcel | `picked_up` | → `out_for_delivery` |
| `in_transit` | Between hubs / long-haul | *new (optional)* | → `out_for_delivery` |
| `out_for_delivery` | Rider heading to recipient | `en_route` | → `out_for_delivery` |
| `delivered` | PIN verified | `delivered` | → `delivered` (COD ⇒ paid) |
| `failed_delivery` | Attempt failed (`failureReason`) | *new* | needs merchant attention |
| `returned` | Parcel returned to merchant | *new* | needs merchant attention |
| `cancelled` | Cancelled by partner, ops or BayanGo | `cancelled` | needs merchant attention (rebook) |

BayanGo must map its internal statuses to these values at the API edge. Internal names can stay as they are.

## 4. Readiness gate (what must be true before Guma sets `BAYANGO_ENABLED=true` in production)

1. Partner API keys work and the partner can only see its own deliveries.
2. `/serviceability`, `/quotes`, `/deliveries`, `/deliveries/{id}` and `/cancel` match this document.
3. Signed webhooks are sent from an outbox with retries, and every status in §3.3 is emitted.
4. `failed_delivery` and `returned` exist. The recipient PIN is sent by SMS and never exposed to riders or partners.
5. Security fixes are in place:
   - `accept()` checks the rider is approved and is the offered courier.
   - No PIN appears in any listing.
   - Ownership checks are enforced on delivery reads.
   - Client money fields are ignored.
   - Status transitions use row locking.
6. Migrations run cleanly on an empty Postgres with `TYPEORM_SYNC=false`, and CI passes (lockfile committed).
7. It is deployed on real infrastructure (not a laptop tunnel), with a sandbox environment Guma can test against.

**Guma-side switches:**
- `BAYANGO_ENABLED`: master switch.
- `BAYANGO_API_BASE_URL`, `BAYANGO_API_KEY`, `BAYANGO_WEBHOOK_SECRET`: connection settings.
- `BAYANGO_PREFERRED`: whether BayanGo wins when it can service the route.
